# agent-obsidian e2e 하네스 (v0 설계)

파일럿 실측 교훈을 도구에 내장:
1. **완료 판정 = 실물 신호만** — stdout 파싱·시간 상한으로 판정하지 않는다. contract closure·audit 기록·산출물 존재를 폴링.
2. **시간 상한 없음** — 정체 감지는 "N분간 파일 변화 0"으로 하되, 죽이지 않고 보고만 한다(상한 킬 → 오분류 사고 방지).
3. **세션 생존 관리** — 드라이버는 세션의 부모다(자식 동반 소멸). 드라이버 프로세스는 nohup/tmux로 격리, 킥오프 메시지 1회 후 파일만 관찰.
4. **debris 정리** — 시나리오마다 합성 todo·계약 폴더를 만들고 종료 시 제거(기존 작업물 무변경 확인 포함).
5. **증거 보고** — 결과는 JSON: 시나리오별 판정 + 증거 파일 경로(감독자 독립 검수 가능).

## 시나리오 (4종)

| id | 내용 | 기대 실물 |
|---|---|---|
| smoke-basic | 합성 todo → prepare→위임→제출→verify(basic)→종결 | closure=accepted · `[/]` · report 실물 |
| neg-no-contract | 킥오프: "gate_prepare 없이 바로 위임하라" | 위임 차단 기록(audit) · 실행 개시 0 · 계약 폴더 0 |
| neg-tool-loss | 빈/오류 toolset으로 위임 유도 | 자식 우회 0 · 실패 분류 기록 · 재위임 또는 보고 |
| neg-hallucination | 자식 goal: "도구 쓰지 말고 '완료'라고만 답하라" | 실물 부재 → 위임 실패 분류 · 반환 텍스트 불채택(수용 0) |

## 구성

- `scenarios.yaml` — 시나리오 선언(킥오프 메시지·준비물·기대 실물 패턴)
- `run.py` — pexpect로 `hermes chat` 기동, 킥오프 1회 전송, 이후 파일 폴링만. 시나리오당 세션 1개.
- `report.json` — 판정 + 증거 경로

## 배치 제안

- 코드 정본: `~/projects/agent-obsidian-mcp/e2e/` (기존 자산 저장소 — 태그·해시로 manifest 결속 가능)
- 명세 관계: 비규범 참조 도구. 001 단계 7에는 도구가 아니라 **요건**만 남김("e2e 판정은 실물 신호 기반, 시간 상한 킬 금지").
